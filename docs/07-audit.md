# 06. 코드 감사 및 개선 이력

## 1. 프로젝트 정보

| 항목 | 내용 |
|---|---|
| 형태 | KISIA 교육과정 4인 팀 프로젝트 |
| 기간 | 2024년 개발, 2026년 10월 코드 감사 및 재구성 |
| 역할 | 팀장: 시스템 아키텍처(Maildir 연동, 감시기와 분석 파이프라인 구조) 설계, 핵심 모듈 구현 주도 |
| 저장소 | 2026년 10월 개인 저장소로 이전. 팀 저장소의 커밋 이력은 포함하지 않음 |

## 2. 감사 결과

2026년 10월, 저장소 코드를 대상으로 정적 리뷰, 전 구간 실행, 학습 데이터 재검증을 수행했다. 확인된 결함은 다음과 같다.

| ID | 결함 | 심각도 | 영향 | 확인 근거 |
|---|---|---|---|---|
| D-01 | 감시기가 저장소에 없는 `python_script.py`를 호출 | 치명 | 메일이 수신돼도 분석 미수행 | 호출 경로와 저장소 파일 목록 대조 |
| D-02 | 파일명을 문자열로 결합해 `system()` 실행 | 높음 | 조작된 파일명을 통한 셸 명령 주입 | 코드 리뷰 |
| D-03 | DOCX 학습 데이터 결함 (악성 929/940건 파싱 실패, 생성 시각 피처 누수) | 높음 | 보고된 정확도 100%가 실제 성능을 반영하지 않음 | 피처별 단일 분할 분류 시 `creation_time` 하나로 96.4% 분리 |
| D-04 | DOCX 추론 시 샘플 1건으로 스케일러를 재학습 | 높음 | 모델 입력이 항상 0, 모든 DOCX에 동일 판정 | 코드 리뷰 |
| D-05 | PDF 학습 피처(SelectKBest 선택 10개, 스케일링 적용)와 추론 피처(별도 10개, 스케일링 미적용) 불일치 | 높음 | 학습되지 않은 입력으로 예측 | 노트북 출력과 추론 코드 대조 |
| D-06 | 데이터 분할 전 SMOTE 적용 | 중간 | 테스트셋에 합성 샘플 혼입, 성능 지표 신뢰도 저하 | 노트북 코드 리뷰 |
| D-07 | 분석 대상을 "수신 폴더의 최신 파일"로 선택 | 중간 | 동시 수신 시 다른 메일을 판정·이동 | 코드 리뷰 |
| D-08 | 첫 번째 첨부만 분석, 첨부 존재 시 링크 분석 생략 | 중간 | 탐지 누락 | 코드 리뷰 |
| D-09 | 동일 기능의 GUI 파일 4종, 컴파일된 바이너리·zip 커밋 | 낮음 | 기준 버전 식별 불가 | 저장소 구성 |

## 3. 근본 원인

결함은 대부분 **구성 요소 간 경계**에서 발생했다.

- **감시기와 분석기 경계** (D-01, D-07): 두 구성 요소 사이에 계약(어떤 프로그램을, 어떤 인자로 호출하는가)이 정의되지 않았다.
- **학습과 추론 경계** (D-04, D-05): 피처 추출과 전처리 코드가 학습 노트북과 추론 스크립트에 각각 존재했다.
- **데이터 수집과 학습 경계** (D-03, D-06): 학습 전 데이터 품질 검증(결측률, 출처 편향) 단계가 없었다.

각 구성 요소는 단독으로 실행 가능했으나, 전 구간 흐름을 검증하는 자동화 테스트가 없어 결함이 드러나지 않았다.

## 5. 교훈

1. **비정상적으로 높은 성능 지표는 누수 점검 대상이다.** D-03은 피처별 단일 분할 검사만으로 발견할 수 있었다. 학습 전 데이터 검증 단계를 표준 절차로 둔다.
2. **학습과 추론은 동일한 코드 경로를 사용해야 한다.** 피처 정의가 두 곳에 존재하면 불일치는 시간 문제다.
3. **구성 요소 간 인터페이스는 명시적으로 정의하고 테스트한다.** 단위 실행 성공은 통합 동작을 보장하지 않는다.
4. **보안 도구의 입력은 공격자가 통제한다.** 파일명, 메일 본문, 압축 파일 모두 신뢰할 수 없는 입력으로 취급해야 하며, 셸 실행, LLM 프롬프트, 압축 해제 각각에 방어 설계가 필요하다.
