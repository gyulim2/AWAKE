## 4. PDF 모델 평가

`python training/train_pdf.py` → `models/pdf_model_card.json`

- 데이터: 정상 102 / 악성 296 (양쪽에 같은 해시가 있는 1건, pdfid 분석 실패 1건 제외)
- 방법: 반복 층화 교차검증 5-fold × 5회, SMOTE는 학습 fold에만 적용

| 지표 | 평균 | 표준편차 |
|---|---|---|
| 정확도 | 0.818 | 0.050 |
| 균형 정확도 | 0.745 | 0.061 |
| 정밀도 (악성) | 0.866 | 0.031 |
| 재현율 (악성) | 0.894 | 0.051 |
| F1 (악성) | 0.879 | 0.035 |
| ROC-AUC | 0.846 | 0.047 |

재학습하면 같은 지표가 나오는 것을 확인했다.

**해석** 악성은 잘 잡지만(재현율 0.89) 정상 PDF를 악성으로 오판하는 비율이 높다(균형 정확도가 정확도보다 낮음). 정상 샘플이 102개뿐인 것이 주원인으로 보인다. 중요도 상위 피처가 파일 크기·페이지 수·객체 수라서, 공격 특성보다 데이터 출처 차이를 학습했을 가능성도 있다.

**이전 수치와의 차이** 이전 노트북의 정확도 0.825는 SMOTE를 데이터 분할 전에 적용해 테스트셋에 합성 샘플이 섞인 상태에서 단 한 번 나눈 결과였다. 수치는 비슷하지만 지금 값이 측정 방법상 더 믿을 만하다.

## 5. 검증하지 못한 것

- **LLM 실제 호출**: API 키 없이 진행해 실제 응답 품질·판정 정확도는 측정하지 못했다. 생략·판정 파싱 로직만 테스트했다.
- **GUI 화면 동작**: 컴파일은 확인했지만, 화면이 없는 환경이라 실제 창을 띄워 보지는 못했다.
- **실제 악성 메일 표본**: 실제 악성 메일 묶음으로 전체 탐지율을 재지는 않았다.
