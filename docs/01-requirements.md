# 01. 요구사항 명세

## 1. 문제 정의

기업 메일로 들어오는 공격은 대부분 사람이 첨부를 열거나 링크를 누르는 순간 시작된다. 기존 스팸 필터는 발신자 평판이나 알려진 시그니처 위주라, 다음 두 경우를 놓치기 쉽다.

1. **첨부 문서 자체에 공격 기법이 숨어 있는 경우** — PDF 안의 JavaScript·자동 실행 동작, Word 문서의 원격 템플릿·매크로·DDE 등
2. **각 요소는 평범한데 조합이 이상한 경우** — "인사팀 연말정산 안내"라는 제목에 첨부는 견적서, 링크는 처음 보는 도메인의 로그인 페이지인 식

A-Awake는 메일 서버에 붙어 들어오는 메일을 자동으로 검사하고, 1번은 첨부 정적 분석으로, 2번은 LLM 문맥 분석으로 잡아 사용자가 열기 전에 격리하는 것을 목표로 한다.

## 2. 범위

| 포함 | 제외 |
|---|---|
| Maildir 형식 메일함으로 배달되는 메일 | 메일 서버(MTA) 자체 구축·설정 |
| PDF, DOCX 첨부 정적 분석 / HWP·PDF·DOCX 본문 텍스트 추출 | 첨부 실행(동적 분석·샌드박스) |
| 제목·본문·첨부·링크의 문맥 분석 | 링크 대상 페이지 실제 방문·평판 조회 |
| 격리, 경고 메일, 판정 근거 기록 | 관리자 웹 콘솔, 다중 사용자 |

## 3. 기능 요구사항

| ID | 요구사항 | 구현 위치 |
|---|---|---|
| FR-01 | 메일 수신 폴더를 감시하다가 새 메일이 완전히 배달되면 분석을 시작한다 | `src/monitor/awake_monitor.c` |
| FR-02 | 감시를 시작하기 전에 이미 쌓여 있던 메일도 처리한다 | `awake_monitor.c` `process_existing()` |
| FR-03 | 메일에서 제목, 발신자, 본문(텍스트·HTML), 모든 첨부, 모든 링크를 추출한다 | `src/awake/mailparse.py` |
| FR-04 | PDF 첨부의 구조 피처를 추출해 악성 확률을 계산한다 | `pdf_features.py`, `attachments.py` |
| FR-05 | DOCX 첨부에서 알려진 악성 문서 기법을 탐지하고 근거를 남긴다 | `docx_rules.py` |
| FR-06 | 제목·본문·첨부 텍스트·링크를 LLM으로 분석해 피싱·악성 여부를 판정한다 | `llm.py` |
| FR-07 | 판정 엔진 중 하나라도 악성이면 메일을 격리 폴더로, 아니면 받은편지함으로 옮긴다 | `pipeline.py` `deliver()` |
| FR-08 | 악성 메일을 격리하면 사용자에게 경고 메일을 보낸다 | `pipeline.py` `_warning_email()` |
| FR-09 | 메일별 판정 결과와 근거를 JSON으로 저장한다 | `pipeline.py` |
| FR-10 | GUI에서 감시를 시작·중지하고, 실시간 로그와 판정 결과 목록을 본다 | `src/gui/awake_gui.c` |
| FR-11 | 메일 한 통을 파일을 옮기지 않고 분석만 해 볼 수 있다 | `python -m awake.pipeline <메일>` |

## 4. 비기능 요구사항

| ID | 분류 | 요구사항 | 확인 방법 |
|---|---|---|---|
| NFR-01 | 보안 | 공격자가 통제하는 값(파일명, 메일 내용)이 셸 명령이나 파일 경로로 해석되지 않는다 | 감시기 `execvp` 사용, 첨부는 임시파일명으로 저장 (코드 리뷰) |
| NFR-02 | 보안 | API 키 등 비밀값을 코드·저장소에 두지 않는다 | 환경변수 `OPENAI_API_KEY` 사용 |
| NFR-03 | 보안 | LLM 프롬프트 인젝션의 영향을 줄인다 | 무작위 구분자, 마지막 줄 판정 (`tests/test_llm.py`) |
| NFR-04 | 보안 | 압축 폭탄·초대형 메일로 분석기가 멈추지 않는다 | ZIP 항목·읽기 크기 상한, 30MB 초과 메일 격리 |
| NFR-05 | 가용성 | 한 엔진(LLM·PDF 모델)이 실패해도 나머지 엔진으로 판정을 계속한다 | 실패는 `status: error`로 기록 (`tests/test_pdf_and_pipeline.py`) |
| NFR-06 | 설명 가능성 | 왜 격리됐는지 사람이 읽을 수 있는 근거를 남긴다 | `reasons`, DOCX `findings` |
| NFR-07 | 재현성 | 모델을 같은 데이터로 다시 학습하면 같은 결과가 나온다 | `training/train_pdf.py` 재실행 시 지표 동일 |
| NFR-08 | 이식성 | 경로는 환경변수로 바꿀 수 있고, 특정 PC 경로를 하드코딩하지 않는다 | `AWAKE_MAILDIR`, `AWAKE_MODEL_DIR` |
| NFR-09 | 품질 | 푸시마다 C 코드는 경고 없이 빌드되고 테스트가 통과한다 | GitHub Actions CI |
